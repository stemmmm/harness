# WORKFLOW

단계별 작업 운용 프레임워크. 단계를 마치면 Codex가 다음 단계로 넘어갈지 사용자에게 묻고, 확인받은 경우에만 넘어간다.

## 역할

- 작업별 담당 모델
  - Sol: 설계 논의, 구현, 테스트, 검증
  - Luna: 코드 리뷰, 테스트 데이터, 문서 초안
- 요청받은 작업이 현재 모델의 담당이 아니면, 서브에이전트를 쓸 수 있을 때는 해당 모델로 서브에이전트를 실행하고, 쓸 수 없으면 해당 모델의 세션에서 진행하도록 사용자에게 안내
- Luna 작업(세션 또는 서브에이전트)은 Sol 작업과 다른 파일만 수정
- 사람: 실무자 질의와 답변 전달, 설계 결정, 승인(설치, 커밋, 단계 전환), 검수, 최종 판단

## 1단계: 세팅과 합의

- 합의문(docs/agreement.md): 실무자와 확인한 요구사항 문서 (templates/agreement.md 형식)
- 사용자가 합의 완료를 알리기 전에는 코드 변경 금지, 읽기와 분석만 수행
- 순서
  - SETUP.md 진행 (docs/HANDOFF.md에 SETUP 완료가 기록돼 있으면 생략)
  - README와 과제 안내 분석
  - agreement Skill로 합의문 초안과 실무자 질문 목록 작성
  - 사람이 실무자에게 질의하고 답변을 전달, Codex는 합의문 갱신 (확인 필요 항목이 없어질 때까지 반복)
  - 사람이 완성된 합의문을 실무자에게 확인받은 뒤 합의 완료를 알림
  - 합의 완료 후 설계는 사용자와 함께 진행, Codex가 아래 항목의 선택지와 장단점을 한 번에 제시하고 사용자가 검토해 결정
    - 요구사항 정리: 합의문에서 기능 요구사항과 비기능 요구사항 정리
    - 데이터 모델
    - API
    - 화면 흐름
    - 핵심 로직 상세 설계
    - 트레이드오프와 위험 요소
  - 확장성, 대규모 처리, 성능, 보안 등은 합의문에 근거가 있으면 설계에 포함하고, 근거가 없으면 하지 않음
  - 결정된 설계를 바탕으로 writing-plans Skill로 docs/PLAN.md 작성 (코드 없이 작업 목록, 검증 방법, 필요한 라이브러리와 도구 및 그 이유)
  - 사용자가 PLAN을 확인한 뒤 프로젝트 기본 구조 생성 (과제에 기존 코드가 있으면 기본 구조 생성 대신 기존 구조 분석과 실행 확인), 필요한 라이브러리와 도구 설치 (설치 규칙은 SETUP.md 공통 규칙과 동일)
  - 서버 기동과 미리보기 연결 확인
- 종료 조건: 사용자의 합의 완료 알림, 서버 기동 확인, 기본 구조 커밋 (기존 코드가 있는 경우 실행 확인)

## 2단계: 구현 루프

- PLAN.md의 작업 순서대로 기능 단위로 진행, 완료한 작업은 PLAN.md에 표시
- 기능마다: 구현 → 관련 테스트 실행 → 서버에서 동작 확인 → verification-before-completion Skill로 완료 전 검증 → 결과 보고 → 사용자 확인 후 커밋
- 핵심 비즈니스 로직은 커밋 전에 Luna(세션 또는 서브에이전트)로 requesting-code-review Skill 리뷰를 먼저 하고 결과를 docs/reviews/에 저장 (리뷰 세션은 코드를 수정하지 않음)
- 이후 Sol이 리뷰 결과와 함께 사용자에게 코드의 구조와 동작을 설명, 그 외 로직은 시간이 부족하면 리뷰와 설명 생략 가능
- 화면 작업은 frontend-design Skill, 원인을 모르는 오류는 systematic-debugging Skill 사용

## 3단계: 검증과 보강

- 새 기능 추가 금지, 결함 수정은 2단계와 같은 확인과 커밋 절차를 따름
- 합의문의 성공 기준마다 충족 여부와 근거(테스트 결과, 화면 확인)를 docs/verification.md에 정리
- playwright Skill로 합의문의 만들 것 전체에 대해 사용자 흐름 확인 (CLI 실패 시 Playwright MCP), 스크린샷은 docs/screenshots/에 저장
- Playwright 확인 후 사용자 검수: Codex가 항목별 결과와 스크린샷을 제시하고, 사용자가 내장 브라우저에서 직접 확인
- 사용자가 검수를 마친 항목만 docs/verification.md에 충족으로 확정
- 엣지 케이스 테스트 보강

## 4단계: 문서와 마무리

- 이 단계에서는 사용자 승인 없이 코드 변경 금지
- submission-doc Skill로 제출 문서 작성 (실행 방법 포함), 코드와 커밋 대조
- 제출 문서의 실행 방법대로 처음부터 서버를 띄워 동작 확인
- 작업 폴더에 불필요한 파일(임시 파일, 테스트 산출물)이 없는지 확인
- 최종 커밋, 커밋되지 않은 변경 없는지 확인
- 사용자에게 핵심 결정, 약점과 그 파급, 장애 시 대응을 짧게 요약해 대화로 제시 (파일로 저장하지 않음)

## 세션 전환 기준

- 아래 시점에 Codex가 handoff Skill로 HANDOFF.md를 갱신하고, 사용자에게 새 세션 시작을 제안
  - 각 단계 종료 시 (다음 단계로 넘어갈지 묻는 시점에 함께 제안)
  - 2단계 안에서는 독립적으로 분리되는 작업 단위가 끝났을 때 (이어지는 작업이면 같은 세션에서 계속하거나 compact 후 진행)
  - 방향을 크게 바꿀 때
- 사용자가 요청하면 언제든 같은 절차로 전환
